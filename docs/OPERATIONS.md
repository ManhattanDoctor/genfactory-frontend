# Разработка и выпуск

## Локальное окружение

Frontend: `http://127.0.0.1:5173`. Backend задаётся `GNOSIS_API_TARGET` только для Vite proxy. `VITE_API_BASE` по умолчанию `/api`; все переменные с `VITE_` публичны, provider keys и client secrets туда не помещаются.

Существующий backend на 3015 в рабочем окружении может быть запущен со старой версией кода. Контракты нужно сверять с выбранным процессом и опубликованным OpenAPI. Сам frontend не меняет backend, его БД или серверную конфигурацию при старте.

## Production

Схема GitHub Actions BUILD → DEPLOY, Docker runtime, SSH secrets и откат описаны в [CICD.md](CICD.md).

Сначала выполните release gates из архитектуры и backend-контракта. `npm run build` создаёт `dist`. Публикация этих файлов не развёртывает gnosis и не настраивает Keycloak.

Reverse proxy должен:

- Отдавать frontend по HTTPS и делать SPA fallback на `index.html` только для маршрутов интерфейса.
- Проксировать `/socket.io/` с WebSocket Upgrade к тому же gnosis; namespace `/gnosisai`, SID передаётся в auth, не URL. При недоступном socket frontend продолжает GET polling.
- Направлять `/api/` в gnosis без fallback на HTML. POST сообщения беседы может ожидать генерацию видео: нужны согласованные upstream/client таймауты не меньше 20 минут. Чтение состояния и истории использует отдельные короткие GET-запросы.
- Не записывать Authorization, cookies, OAuth code, промпты или содержимое сообщений в access/error logs.
- Возвращать корректный cache policy: hashed assets — immutable, `index.html` — revalidate, персональные API — private/no-store.
- Ограничить размер загрузки и частоту запросов в соответствии с backend. UI-ограничение в 20 МБ для референса не заменяет серверное.
- Настроить точный CSP для application origin, auth origin и media host; не разрешать произвольные scripts. Шрифты поставляются локально через Fontsource, запросов к Google Fonts нет.

В Keycloak разрешить точные redirect URIs `/auth/callback` для staging/production. Не добавлять wildcard на неизвестные домены. Для cookie-auth отдельно настроить CSRF и Origin, не считать CORS достаточной защитой.

## Тестовая матрица

1. `npm ci`, `npm run build`, `npm test`, `npm run test:e2e`, `npm audit`.
2. Desktop 1440px и mobile 390px: обзор, меню, редактор, библиотека, модальный просмотр, клавиатура и Escape.
3. Read-only smoke с настоящим gnosis: init, image/video/assistant catalog, conversation/message lists, file list, account balances; токен не выводится в логи и не сохраняется в fixture.
4. На staging по согласованному бюджету: одна image и одна video генерация, проверка сохранённого файла и финансовой записи. Это отдельная проверка, не скрытый шаг CI.
5. Проверки устойчивости бесед: refresh/reconnect, повторная отправка, перезапуск процесса во время работы, восстановление связи video job с сообщением, отсутствие двойного списания; сессии — expire/logout/revoke; media — недоступность чужих файлов.

## Наблюдаемость

Для диагностики используются conversation ID, execution ID, task/billing operation ID и video job ID. Метрики: длительность работы, ошибки инструментов, доля несохранённых результатов и задержка окончательного расчёта стоимости. Логи содержат безопасный код ошибки; промпты и медиа не отправляются в аналитические сервисы по умолчанию.

Клиентская аналитика, если будет добавлена: просмотр экрана, выбор сценария, начало загрузки, submit/состояние результата. Без сырого prompt, SID, email или URL приватного медиа. Для начала внешняя аналитика не подключена.

## До подготовки первого production выпуска

Старый сайт `genfactory.ru` и его сервисы не изменялись. Исходный сервер использовался для чтения HTML/CSS/JS; медиа взяты с публичного сайта. Не выполнялись миграция старых пользователей, перенос балансов, push в GitHub или production deploy.

## Функциональная проверка новой студии — 2026-11-01

Проверка дополнена сценариями повторного входа в редактор с закэшированным каталогом, переноса промпта из подборки, восстановления другой модели с референсом, загрузки/удаления вложений, запоздалого upload после новой работы, ошибок каталога и библиотеки, пагинации истории/сообщений, OAuth callback, обновления баланса и недоступного медиа.

Исправлены сбросы референсов и промпта при инициализации, присоединение завершившейся загрузки к другой работе и сброс ввода после перехода к новой беседе. Некорректная/недоступная беседа больше не показывает постоянную загрузку; пустой поиск и недоступное медиа имеют явные состояния. Проверены семь экранов при ширине 1440 и 390 px, без горизонтального переполнения и JS-исключений. Пять старых медиа в библиотеке не загрузились: UI отображает недоступность, сами файлы не восстановлены.

Проверена настоящая загрузка тестового PNG, его появление в библиотеке и перенос в редактор; созданные проверкой файлы 95 и 96 удалены после проверки. Повторно проверено воспроизведение ранее созданного видео из беседы 46. Новые платные генерации не запускались. В Playwright используется небольшой сгенерированный одноцветный MP4, не пользовательский файл.

### Проверка локального рабочего пространства

- Написать запрос, выбрать модель и добавить референс; перезагрузить страницу и нажать «Восстановить черновик». Проверить сохранённые параметры и доступность файлов.
- Переставить два референса кнопками или перетаскиванием; проверить порядок перед отправкой, особенно первый/последний кадр видео.
- В библиотеке открыть результат, переключить файл и применить «Использовать как референс»: должен передаваться текущий файл просмотра.
- В «Правилах бренда» экспортировать настройки; импортировать JSON, проверить содержимое до применения. Импорт заменяет только переносимые локальные настройки.
- Панель «Работы» показывает серверные статусы и ошибки загрузки. Уведомление о завершении не заменяет проверку ответа ассистента.

### Варианты и отступы форм

В беседе открыть «История вариантов», выбрать «Повторить с изменениями». Проверить запрос, модель, качество и порядок референсов; до отдельного создания новый платный запрос не отправляется. У старой работы без локальной записи параметров должно отображаться предупреждение. Проверить сохранение параметров после перезагрузки и отсутствие повторного добавления инструкций бренда.

На ширинах 1440 и 390 px раскрыть «Сохранить как шаблон», «Съёмка и стиль», «Инструменты». Между summary и содержимым используется отступ 20 px, между полями и действиями — 16 px, подписи полей остаются связанными с контролами.

## Подготовка первого production выпуска — 2026-11-02

Закрыты история баланса (настоящие проводки, направление операции, источник, точная сумма и подтверждённая разбивка), фильтр периода, блокировка нового шаблона из-за чужой активной беседы и отступы истории работ. Для DATE-фильтра API требуется timestamp в миллисекундах, а не ISO-строка. Точные денежные суммы форматируются через BigInt, без потери дробных копеек. Проверки: 37 unit и 72 e2e, production build; страницы баланса и истории просмотрены на 1440/390px без переполнения и ошибок JavaScript.

Production домен нового клиента — `https://genfactory.gnosisai.ru`; внешний vhost хранится в `gnosis-frontend/nginx/gnosisai.ru`. Контейнер `genfactory-frontend`, loopback-порт 8081, API `https://api.gnosisai.ru`. Для CI используется текущий SSH-ключ, по указанию пользователя; секреты хранятся в репозитории, приватный ключ не входит в код. Основной `gnosisai.ru` остаётся на прежнем контейнере/порту 8080.

Локальный API использует БД `gnosis`, production API — `gnosisai`. Тестовые локальные беседы, файлы и балансы не переносятся автоматически. На production показываются аккаунты и данные production gnosis. Старые данные Genfactory и локальные тестовые данные не мигрировались.

### Выход из аккаунта и Keycloak

Кнопка выхода завершает локальную сессию, вызывает `POST /logout` и переводит браузер на Keycloak `protocol/openid-connect/logout`. Передаются `client_id`, доступный `id_token_hint` и `post_logout_redirect_uri` на `/account`. Ошибка API выхода не блокирует завершение SSO; сетевые запросы ограничены 10 секундами. Для старой сессии без ID-токена Keycloak может попросить подтвердить выход.

В клиенте Keycloak должны быть разрешены точные адреса возврата после выхода:

- `https://genfactory.gnosisai.ru/account`
- `http://localhost:5173/account`
- `http://127.0.0.1:5173/account`

Для проверки смены аккаунта: выйти, завершить подтверждение Keycloak, если оно появилось, затем снова нажать «Войти». Должна открыться форма входа. Вход у внешнего провайдера (например, Google) управляется отдельно самим провайдером.
