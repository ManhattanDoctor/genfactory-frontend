# Студия контента: перенос прототипа 1:1

> История этапов. Актуальное сопоставление требований, прототипа и нашей реализации ведётся в [реестре расхождений](IMPLEMENTATION-DIFFERENCES.md). Ограничения ранних этапов ниже не описывают автоматически текущее состояние.

Проверено 2026-11-03 по опубликованной локальной копии `../prototype`, исходному backend `../prototype-backend` и браузеру при 1440 × 1000. Генерации при исследовании не запускались. Это карта реализации, не отчёт о завершённом переносе.

## Подтверждённый интерфейс

- Слева рабочая область беседы с точечным фоном. Справа галерея с вкладками «Шаблоны» и «Настройки».
- Пустая беседа содержит две исходные рукописные подсказки со стрелками.
- Поле ввода закреплено внизу рабочей области; переключатель изображения, видео и презентации расположен над ним. Исходный режим — видео.
- В нижней строке: добавление файла, модель Auto, длительность, звук, один кадр/набор сцен, соотношение сторон и отправка. Видимость настроек зависит от режима.
- Enter отправляет, Shift+Enter оставляет перенос строки. Поле растёт с 72 px до ограничения около 122 px.
- Справа есть жанры, фильтр избранных, избранное отдельного шаблона и три ширины панели: s/m/l. Предпочтения сохраняются.
- Галерея видео использует `media/creatives/catalog.json`, изображения — `media/images/templates.json`, презентации — `media/creatives/slides.json`. Сохранять исходные карточки, SVG, тексты и видеопревью.
- Нажатие «Добавить» добавляет шаблон в pendingTemplates отдельным материалом; текст поля при этом не подменяется. Повторное добавление того же файла игнорируется.
- Выбор шаблона для начального/конечного кадра заполняет соответствующий слот, а не общий список шаблонов.

## Настройки

Общие: «Сценарист» (изначально включён), «Дизайн-система» (недоступна без сохранённых правил).

Видео: начальный и конечный кадры, формат, идея, обстановка, камера, движение, линза, свет, качество. Исходные значения: 9:16, 8 с, без звука, один кадр, качество 720p; остальные — исходные «Авто», «Нет», «Не задано».

Изображение: формат, идея, обстановка, линза, свет, качество. Настройки кадров, движения камеры и длительности не показываются.

Презентация: исходное сообщение «Для презентации дополнительных настроек съёмки нет».

Параметры конкретной модели должны проверяться по каталогу Gnosis. Если исходное значение не поддерживается, не подменять его молча: требуется согласованное поведение.

## Подтверждённая отправка

1. Собрать текст, выбранные шаблоны, вложения, кадры и настройки.
2. Создать проект при первом запросе; сохранить настройки и сообщения в существующий проект при продолжении.
3. При включённом сценаристе и отсутствии шаблона выполнить отдельный запрос роли writer; показать стадию «Собираю промт.».
4. Полученный текст передать генерации; показать «Собираю...».
5. При наличии шаблона этап writer пропускается.
6. Получать результат серверной задачи и восстанавливать незавершённые задачи после возврата. В Gnosis переиспользовать существующую доставку через сокет, а не переносить HTTP polling прототипа.
7. Презентация возвращает текст по слайдам с указанием «Файла презентации нет». PPTX/PDF не реализован в оригинале.

Auto в исходном `selectedModel()` для авторизованного пользователя — первая подключённая модель нужного типа, если пользователь не выбрал конкретную. Это не отдельный интеллектуальный подбор модели. Frontend для гостей выбирает бесплатную текстовую модель, но backend `app/gate_auth.py` разрешает без входа только `mode=talk, role=guide` на главной. Отправка из студии требует входа. Выбор FreeModels во frontend сам по себе не подтверждает доступность гостевого запуска.

## Что переиспользовать из текущего клиента

- `AuthProvider` и `LoginDialog`: аккаунты Gnosis / Keycloak.
- `api`, существующие беседы и сообщения: сохранить серверные идентификаторы и проверку владельца.
- `features/catalog/schema.ts`: значения, допустимые параметры, ограничения референсов и валидация по схеме.
- `features/studio/conversations.ts`: IMAGE/VIDEO и настройки инструментов; не повторять сборку тех же payload.
- `features/realtime`: статусы и результаты через сокет.
- Существующие загрузку, отображение прогресса и типы файлов.
- `usePreferences`: избранные шаблоны и правила бренда с привязкой к аккаунту.
- `creativePrompt`: сборка правил бренда и пожеланий к съёмке.

Текущий `/chat` использует `TextStudio` с инструкцией для обсуждения и отдельным выбором инструментов. Его нельзя выдать за перенесённую студию после косметических изменений. Новую страницу подключать к `/chat` только после проверки согласованного сценария, не ломая `/prompt`, `/script` и `/agent`.

## Этап интерфейса — 2026-11-03

Маршрут `/chat` без параметра `conversation` теперь открывает новый `ContentStudio`. Существующие беседы `/chat?conversation=…` пока открываются в прежнем `TextStudio`: перенос экрана результатов не входит в этот визуальный этап.

Перенесены исходные локальные шаблоны (30 видео, 130 изображений, 126 презентаций), SVG режимов и настроек, шрифт Caveat, изолированные CSS-правила исходника. Работают переключение режима, панелей, ширины галереи, жанры, избранное, выделение и добавление шаблона отдельным материалом, настройка съёмки, выбор локальных файлов и кадров. Список моделей для вошедшего пользователя читается из существующего каталога Gnosis; модель на этом этапе выбирается только в состоянии интерфейса.

### Временные ограничения этапа (не скрывать при демонстрации)

- Отправка для вошедшего пользователя пока отключена: новая цепочка генерации не подключена. Гостевой submit открывает существующий вход Keycloak.
- Файлы и параметры пока живут в состоянии страницы; выбранные файлы не загружаются на backend. Генерации и списания не выполняются.
- Сценарист и дизайн-система пока только переключатели состояния; их применение будет подключено вместе с отправкой.
- Мобильный интерфейс сохраняет доступность и складывает области вертикально. В опубликованном прототипе мобильный доступ закрыт; это существующее отличие клиента, а не подтверждённое совпадение с оригиналом.
- Избранные гостя сохраняются локально отдельно от аккаунта; избранные вошедшего пользователя используют существующие preferences Gnosis-клиента.

Проверено: сборка TypeScript/Vite; браузерные сценарии переноса текста с главной, избранного после reload, выбора шаблона без подмены текста запроса, настройки камеры, переключателя сценариста, режима презентации и ширины галереи. Запросов создания беседы/генерации в проверках нет.

## Уточнение цепочки по исходному коду — 2026-11-03

Исследование кода, без платных запусков. Предыдущее описание «writer → генерация» неполно: платная отправка image/video выставляет `brief=true`, после чего сервер запускает planner. Он проверяет материалы и совместимость модели, вызывает текстовую модель для структурированного плана, валидирует ответ и при необходимости пытается исправить план. Выключение сценариста не выключает этот этап.

Обнаруженные ограничения опубликованного клиента:

- `pickTemplate` сохраняет только file/title/kind. `syncTemplates` обновляет выделение галереи; `modelPrompt` не читает шаблоны. В исследованном `askStudio` шаблоны и их промпты не входят в payload. Их наличие при этом отключает writer. Влияние выбранного шаблона на генерацию этим кодом не обеспечено.
- `askStudio` отправляет только изображения из attachments; `fileData` пропускает JPEG/PNG/WebP. Выбор документа, аудио или видео не означает отправку их содержимого. Серверный planner отдельно блокирует audio/video.
- Загруженные начальный/конечный кадры становятся обычными attachments без роли слота; шаблонные кадры остаются в templates. Семантика кадров при отправке теряется.
- Презентация остаётся текстом. Auto — первая подключённая модель, не интеллектуальная маршрутизация.

Сопоставление с Gnosis без изменений backend: проект → Conversation; пользовательская задача → сообщение с файлами и settings.tools; генерация → существующие IMAGE/VIDEO инструменты; технические параметры → каталог и tool settings; творческие пожелания и бренд → текст инструкции; обновления → существующие сокеты. Серверные проверки каталога уже есть, но отдельный planner прототипа с проверкой структурированного плана этим автоматически не воспроизводится.

В `VideoOpenRouterTool.getFrameImages` один fileId означает первый кадр, два — первый и последний по порядку. Сценарий только конечного кадра через этот инструмент сейчас не выражается. Не подменять его первым кадром молча; поведение требует согласования.

Предложение к обсуждению: сначала подключить новый интерфейс к существующей цепочке upload → conversation → message/tools → socket/results. Поведение сценариста, применение шаблонов и ограничение отдельного конечного кадра согласовать до реализации: визуально сохраняем исходник, но не выдаём его незавершённые функции за работающие.

## Подключение к Gnosis — 2026-11-04

Выполнено в первом функциональном этапе: создание/открытие беседы в новом ContentStudio, отправка IMAGE/VIDEO через существующие tools, загрузка изображений с прогрессом и передачей fileIds, текстовый сценарист, отображение сообщений и файлов, действия «Изменить»/«Оживить» с фокусом в поле, подписка на существующие события, загрузка состояния после reload. Режим и настройки медиинструмента восстанавливаются из options беседы.

Важное уточнение API: settings.tools сообщения переопределяет настройки подключённых инструментов, но НЕ заменяет список инструментов. Пустой массив не отключает генерацию. Поэтому перед текстовым этапом через существующий PUT беседы сохраняется options.tools=[], перед генерацией — только выбранный IMAGE или VIDEO. Backend не изменялся. Параллельная отправка из разных вкладок остаётся ограничением: frontend не может сделать PUT+POST атомарными.

Проверки первого этапа выполняются браузерными тестами с тестовым API. Пользователь дополнительно разрешил реальные недорогие запросы: результат этих проверок будет записан отдельно; тестовые ответы не считать живыми генерациями.

- Изображение: `gpt-image-1-mini`, файл **155**, готовое превью.
- Видео: `x-ai/grok-imagine-video-1.5-lite`, файл **156**. Лог вызова содержит `fileIds: [155]`, сохранённый origin видео содержит `sourceFileIds: [155]`: именно созданная чашка передана референсом.
- Видео успешно восстановлено после закрытия страницы и повторного открытия. ffprobe: длительность 4.041667 с, фактический размер 960×960; image/video preview имеют статус READY.
- Живая проверка двух вкладок: новая текстовая задача отправлена первой вкладкой; вторая получила ответ, наблюдала 6 событий ConversationChangedEvent и не отправила ни одного сообщения. После reload ответ сохранился.

Выявленные расхождения параметров (не маскировать):

1. В запросе изображения frontend передал `quality=low`, но ассистент явно вызвал инструмент с `quality=high`. Существующая серверная семантика допускает переопределение настроек аргументами инструмента. Инструкция ассистенту не является строгой гарантией. Для гарантированного соблюдения выбранных параметров требуется отдельно обсудить серверный механизм фиксации параметров.
2. После смены image→video значение low ранее попадало в resolution. Это frontend-дефект, исправлен: отображается и передаётся совместимое разрешение видео 720p.
3. Видеопровайдер вернул квадратный файл 960×960 с аудиопотоком при запросе 9:16/720p/без звука. Наличие аудиопотока само по себе не доказывает слышимый звук. Соответствие фактического результата параметрам провайдера требует отдельного разбора; не заявлять полное соблюдение параметров.

### Внешний вид беседы и контролов

- Исправлены обёртки dropdown: стрелка выбора модели больше не накладывается на обычные чипы; подпись длинной модели сокращается отдельно от стрелки.
- Структура сообщений перенесена из `assistant-chat.js`: объединённый блок user/bot, аватары, исходные классы, действия «Повторить запрос», «Скопировать текст», «Скачать». Повтор возвращает текст в поле и не запускает оплату; это соответствует оригиналу, но ещё не является точным восстановлением рецепта.
- Правка/оживление доступны в существующем просмотрщике файла. Полноценного отдельного действия применения сценария пока нет.
- Исправлены отступ под плавающим composer и прокрутка; при чтении истории не выполняется принудительный переход вниз, есть исходное «К новым».
- По прямому пожеланию пользователя ответы отображаются существующим Markdown-компонентом: `[Смотреть видео](URL)` становится кликабельной ссылкой, ролик остаётся встроенным. Это намеренное отличие от textContent оригинального AssistantTurn.
- Метаданные конкретного прошлого запуска (модель/длительность) не подменяются текущими настройками беседы. Пока в чипах результата показывается только подтверждённый тип файла.
