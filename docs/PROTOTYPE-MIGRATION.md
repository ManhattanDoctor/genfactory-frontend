# План переноса интерфейса Genfactory

Статус: подготовка завершена; первый этап в работе. Основа — опубликованный прототип `../prototype`, рабочие исходники `../prototype-source`, отдельная копия backend `../prototype-backend` и документ заказчика «Правки витрины.docx». Разработка ведётся в существующем React-клиенте с API, аккаунтами, балансами, беседами, файлами и сокетами Gnosis.

## Как принимаем решения

Внешний вид сверяем с живым прототипом, продуктовые пожелания — с документом заказчика, возможности — с действующим каталогом и контрактами Gnosis. Промпты для Claude из документа считаются описанием намерений, а не готовыми техническими заданиями. Числа моделей, имена, оценки и цены не переносятся в код как постоянные значения.

Текущие возможности сохраняются: TTS/STT, библиотека с папками и ссылками, настройки инструментов, прогресс загрузки, референсы, шаблоны, история баланса, превью, сокеты и восстановление работ. Меняется их размещение. Старые адреса продолжают открываться; скрытие пункта навигации не означает отключение функции.

| Убрать отдельные аудио, библиотеку, шаблоны, стиль бренда    | Переносим точки входа: аудио — в студию, файлы — в историю и выбор вложений, шаблоны — в контекстную панель, стиль — в аккаунт. Сначала создаём новые точки входа, затем убираем старые.     |
| История якобы только в браузере                              | Неверно: беседы и файлы уже серверные. Отдельно дорабатываем серверные черновики, избранное, архив и настройки.                                                                              |
| Удаление через 14 суток                                      | Не вводим автоматически. Нужна отдельная продуктовая политика хранения, согласованная до реализации удаления. Не показываем выдуманную дату истечения.                                       |
| Показать 0 вместо неизвестного баланса                       | Не принимаем. Ноль — только подтверждённое значение; загрузка и ошибка различаются. Сам документ содержит оба противоречащих требования.                                                     |
| Вход без Keycloak-редиректа                                  | Сохраняем принятую авторизацию Keycloak. Убираем лишние объяснения реализации и промежуточные шаги. Брендирование страницы SSO — отдельная работа; собственную парольную форму не добавляем. |
| Убрать «Работы 0»                                            | Убираем дублирование в шапке, но сохраняем доступ к активным задачам и их статусам. Активные задачи и история — разные функции.                                                              |
| Фиксированные 58/35 моделей и названия из примеров           | Используем актуальный каталог Gnosis. Не выдаём модель за другую через маркетинговый псевдоним. Отсутствующая модель не заменяется молча.                                                    |
| Цена до запуска, отмена, undo, отсутствие двойного списания  | Только по реальным гарантиям backend. Блокировка кнопки и отсутствие автоповтора нужны, но не заменяют серверную идемпотентность.                                                            |
| Презентация и отчёт проекта                                  | Текстовый план слайдов не объявляем PPTX/PDF. Проверяем существующие инструменты экспорта; полноценный файл — отдельный этап при отсутствии такого инструмента.                              |
| Auto, агент знает модели и цены                              | До запуска нужен подтверждаемый выбор. Знания о каталоге/ценах — только через данные и инструменты Gnosis. Не угадываем стоимость текстовой моделью.                                         |
| Оверлей Claude и склейки текста                              | Проверяем воспроизведение и принадлежность нашему UI; не удаляем сообщения о реальных ошибках на основании чужого скриншота.                                                                 |
| Pixel-perfect и мобильная приёмка                            | Сравниваем на фиксированных viewport и одинаковых состояниях; функциональные отличия описываем. Эмуляция WebKit не считается проверкой физического iPhone.                                   |

По последнему указанию пользователя работа идёт по страницам. Сначала сверяем документ с фактически работающим прототипом: [постраничный аудит](PROTOTYPE-PAGE-AUDIT.md). Ранее сделанная оболочка и Главная остаются локальным черновиком; следующая работа — согласовать поведение Главной по аудиту.

## Текущий следующий шаг

Первый проход этапа 1 реализован локально: навигация, главная, передача задачи, примеры и последние работы. Следующий шаг — постраничная сверка Главной с прототипом и документом; общий ввод и пикер выделяем по мере реализации согласованных страниц. Рабочие редакторы пока используют прежнюю компоновку. Временная группа «Рабочее пространство» сохраняет доступ к аудио, файлам, шаблонам, сценарию и стилю бренда до переноса этих функций. `/agent` использует существующий текстовый редактор; специализированное оформление относится к этапу 4. Копия прототипа остаётся отдельной и не используется как backend приложения.

Проверка локального черновика: build и 47 unit-тестов прошли. В полном браузерном прогоне прошли 109 из 112 сценариев; три оставшихся успешно перепроверены после восстановления доступного имени ссылки аккаунта и уточнения селектора входа внутри основной области страницы. Отдельно прошли проверка мобильного меню с возвратом фокуса и проверка главной в WebKit. Дальнейшая работа ведётся по страницам, начиная с уточнения сценариев Главной.
