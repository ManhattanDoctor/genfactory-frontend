# Перенос витрины GenFactory на рабочий фронтенд

Цель — воспроизвести семь разделов кликабельной витрины один в один в существующем React-приложении. Эталон для этой работы лежит в ~/Downloads/Genfactory/GenFactory-витрина-для-разработки. Запись экрана рядом с каталогом показывает последовательность действий и переходы. PDF от 18 ноября дополняют сценарии. Например, на главной в PDF описаны карточки с иконками, а в витрине и записи показаны три медиакарточки. Для главной воспроизводим медиакарточки. Другие расхождения фиксируем в [реестре](IMPLEMENTATION-DIFFERENCES.md) и согласуем до реализации спорного элемента.

## Порядок переноса

Каждая строка — отдельный локальный показ и приёмка пользователем перед переходом к следующей странице.

| -------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Главная     | / · Home                         | Сначала общая оболочка, шрифт Manrope, цвета, иконки, размеры и состояния бокового меню. Затем три медиакарточки с оригинальными обложками, воспроизведением и переходами в нужный режим. Сверить порядок ленты, переход между «Генерации» и «Дайджесты», открытие и возврат из дайджеста, добавление девяти карточек по «Показать ещё». |
| 2. Изображения | /image · Studio, MediaWorkspace  | Воспроизвести расположение ленты и формы, выбор и поиск модели, избранное, информацию о модели, пропорции и поля вложений. Пройти путь от выбора шаблона до просмотра результата. Сверить, что после смены модели видимые поля и запрос соответствуют её возможностям.                                                                   |

| 4. Студия      | /chat · ContentStudio            | Перенести начальный экран, диалог, предложения, ввод своего варианта, переключение изображения и видео, действия с результатом. Проверить сворачивание и изменение ширины правой панели, вкладки шаблонов и настроек, положение поля ввода при прокрутке и открытие панели на телефоне.                                                  |

## Как принимаем один экран

1. Перед правкой открыть соответствующий раздел витрины и его HTML, CSS, JS и данные. Зафиксировать исходное состояние, используемые файлы, точки смены компоновки и действия, меняющие экран. Переносить используемые оригинальные шрифты, иконки, обложки, изображения и ролики с их кадрированием и порядком.
2. Открыть витрину и рабочий маршрут в одном браузере при одинаковых ширине, высоте, масштабе и данных. Снять парные скриншоты на десктопе, на телефоне шириной 390 px и по обе стороны от точек смены компоновки страницы. Для видео выбрать один кадр. Наложением сверить геометрию, текст и его переносы, отступы, положение панелей, размеры и цвета.
3. Повторить одинаковые клики, прокрутку, наведение, фокус с клавиатуры и касания. Сверить момент запуска превью, длительность переходов, закрытие меню и возврат на предыдущий экран. Для открывающихся панелей и диалогов сравнивать также экран после действия.
4. Для визуальной пары использовать одинаковый воспроизводимый набор данных. Рабочий сценарий проверить отдельно на существующем Gnosis API с настоящими идентификаторами моделей, задач и файлов. Для генерации проверить отправку, ожидание, результат и ошибку с пользовательским текстом по коду из details. Для аккаунта использовать данные авторизованного пользователя. Если показанное дизайнером действие требует нового контракта или у состояния ошибки отсутствует макет, записать конкретное расхождение и согласовать решение.
5. После завершения страницы выполнить прицельные проверки затронутого сценария. Предоставить две локальные ссылки, пары скриншотов и короткий маршрут для ручной проверки. Закрывать этап после сверки видимых расхождений и подтверждения пользователя.

## Завершение

После приёмки семи страниц пройти сквозной путь с главной через генерацию к результату, истории и библиотеке. Проверить переходы между разделами с раскрытым и свёрнутым меню и на телефоне. Подготовить изменения к Astra-ревью относительно последней метки astra. Для запуска ревью дождаться подтверждения переключения модели. Выкладка на демо — после ревью и команды пользователя через GitHub Actions с проверкой фактической ревизии.
