# Соответствие прототипа документу заказчика

Задача — установить фактическое поведение каждой страницы genfactory.ru до переноса в наш клиент. Документ «Правки витрины.docx» объединяет описание прототипа, пожелания и критерии будущей реализации; они не равнозначны.

Проверены опубликованные HTML/JS в `../prototype`, действующий backend в `../prototype-backend/site/service`, публичные GET API сервера и локальные взаимодействия с копией. В браузерной проверке разрешались только GET к API оригинала, POST блокировались. Для локального просмотра ранее исправлен один цикл восстановления гостевой сессии; этот факт не означает исправления production. Сценарии с личным аккаунтом, платные операции и реальные мобильные устройства здесь не принимались.

Обозначения: «есть UI» — элементы и обработчики доступны в опубликованном клиенте; «есть backend» — найден действующий серверный обработчик; «пожелание» — соответствующий сценарий не найден в проверенной реализации. Наличие обработчика не означает прохождения полного сценария на production.

## Видео

Есть UI ленты, нижнего ввода, выбора моделей, референса, длительности, соотношения, звука и шаблонов. Конкретный набор зависит от их каталога; не каждая модель поддерживает все чипы из документа. Есть просмотр, повтор, скачивание и архивирование.

Требование «уведомление без открытой вкладки» не подтверждается клиентом: состояние задач проверяется HTTP-опросом через `job-watch.js`. Полноценную отмену на стороне каждого поставщика нельзя заключить из наличия action cancel: backend отмечает запрос отмены, а гарантии остановки и списания требуют отдельной проверки.

Основные файлы: `../prototype/videos-wall.js`, `../prototype/job-watch.js`, `../prototype-backend/site/service/studio_gate.py`.

## Студия контента

Есть диалог, переключение типов результата, шаблоны, настройки, режим помощи с формулировкой задания, серверные операции сохранения и переименования диалога. Есть очередь и восстановление задач на backend.

При этом:

- Презентация — текст по слайдам. Код явно добавляет «Файла презентации нет». Готовая PPTX/PDF-презентация и сборка такого отчёта по проекту — дополнительные пожелания.
- Архив работ и повторное использование результата не равны полноценному дереву версий с возвратом на любую версию.
- Структурированный Auto с показом выбранной модели и типа до запуска не подтверждён как единый готовый сценарий.
- Одинаковые внешне поля ввода реализованы отдельными скриптами разных разделов. Единый переиспользуемый компонент — требование к нашей реализации, не готовый компонент, который можно забрать из прототипа.

Основные файлы: `../prototype/creatives-chat.js`, `../prototype/creatives-store.js`, `../prototype-backend/site/service/content_store.py`, `../prototype-backend/site/service/studio_gate.py`.

## История

Реальный экран `/history` — панель с id `library`. Она богаче краткого описания документа: есть вкладки «Работы», «Диалоги», «Потребление», поиск, фильтры, архив/избранное, задачи и выгрузки. URL хранит состояние части фильтров.

Серверные работы и диалоги действительно есть. В `content_store.py` и `jobs_store.py` установлен срок 14 суток и реализована очистка. Для работ срок считается по created_at; для старых диалогов очистка использует updated_at. Это не универсальный срок всех сущностей: кабинет имеет другую настройку retention.

Поиск по тексту выполняет клиентский `HistoryBoard.filterWorks()` над полученными записями. Серверный `list_works()` поддерживает тип, поверхность, архив/избранное, курсор и лимит, но не текстовый поисковый запрос. Поэтому требование полноценного серверного поиска по всему архиву не следует считать уже выполненным.

Точное отображение даты удаления у каждой работы, полный undo и безусловное восстановление всей цепочки версий не подтверждены. Подпись о локальных черновиках в нашем клиенте не означает, что история Gnosis хранится только локально.

Основные файлы: `../prototype/history-board.js`, `../prototype/creatives-chat.js`, `../prototype-backend/site/service/content_store.py`, `../prototype-backend/site/service/jobs_store.py`.

## Мой аккаунт и вход

- Email/password-вход и сессии реализованы их собственным backend; это другая архитектура, не настройка нашего Keycloak.
- Кабинет имеет аналитику и CSV-выгрузки через `/api/auth/cabinet` и `/api/auth/cabinet.csv`.
- Стиль бренда и опубликованные версии в `account.js` хранятся через localStorage (`cw-company-v1`, `cw-design-published-v1`). Серверная межустройственная синхронизация этих настроек не подтверждена.
- Для части материалов кабинет сохраняет имя и извлечённые правила; сам код показывает сообщение «Сам файл на сервер не уходит». Наличие карточки материала не доказывает полноценную файловую библиотеку.
- Экспорт/импорт всей конфигурации — шаблоны, правила, избранные модели — в единый JSON из документа не найден как готовый сценарий опубликованного кабинета. CSV-аналитика и внутренний import_content — другие функции.
- Публичный `/api/health` сообщает `payment: false`, OAuth Яндекс/VK/Gazprom — false. Приём оплаты нельзя считать работающим.

Основные файлы: `../prototype/account.js`, `../prototype-backend/site/service/app/http_api.py`, `../prototype-backend/site/service/app/billing.py`.

## Как двигаться дальше

Работаем по одной странице: фактический эталон → таблица отличий нашего экрана → согласованный набор поведения → реализация → локальный просмотр. Не начинаем с общего переписывания всех редакторов.

Первая страница — Главная. Для неё отдельно решаем два расширения относительно оригинала: консультант или маршрутизация задачи; галерея просмотра или полноценные шаблоны с промптами. Действующий оригинал не содержит второго варианта автоматически.

Ранее сделанные изменения оболочки и Главной остаются локальным черновиком. Их нельзя считать принятой копией эталона: поле пока переносит текст в наш чат, тогда как оригинал отвечает прямо на Главной. Дальнейшая доработка идёт после этого сопоставления.
