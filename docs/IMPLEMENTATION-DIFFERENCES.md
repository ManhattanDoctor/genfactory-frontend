# Genfactory: фактическое состояние и расхождения

Обновлено: **2026-11-05**. Это основной актуальный реестр для обсуждения с заказчиком и выбора дальнейшей реализации. Он разделяет **требования документа**, **реализацию прототипа**, **наш текущий код** и **предложения**. Наличие кнопки не доказывает выполнение функции; наличие функции в Gnosis не означает её подключение в новом интерфейсе.

Наше состояние здесь — **локальный frontend**, а не подтверждённая версия на стенде. Основной перенос интерфейса использует существующие API; отдельно согласованные изменения backend для метаданных и читаемых имён результатов описаны ниже. Весь перенос не завершён и не принят как копия 1:1.

## Текущий этап 2026-11-05 — существующий backend

Пользователь выбрал доработку страницы изображений без нового серверного планировщика. Предложения серверной схемы в аудите ниже не приняты к реализации. Этот блок заменяет прежнее описание текущего поведения шаблонов и «Переделать»; исторические проверки относятся к прежним версиям.

- **Избранные модели:** по запросу пользователя единое поведение — фильтр «Избранные», без сортировки после лайка. ImageWorkspace приведён к существующему ContentStudio и ModelBrowser; используется общий список favoriteModels, общие стили фильтра. Намеренное согласованное отличие от сортировки прототипа images-wall.js.
- **Шаблоны:** обязательная замена всех меток и предположительное требование фото сняты. Пустой шаблон по-прежнему не отправляется; ограничения референсов конкретной модели сохранены. Идея и шаблон передаются отдельными разделами сообщения текущему ассистенту. Инструкция требует уточнять важные пробелы до IMAGE, не спрашивать необязательные детали, соблюдать выбранные настройки. Это инструкция модели, а не гарантированный серверный planner/locked settings. Служебные инструкции скрываются при отображении сообщения.
- **Переделать:** добавляет готовый кадр после исходников, без повторной загрузки, проверяет принадлежность файлов, поддержку и лимит референсов. При несовместимости задание не меняется; отправка только вручную. Для новых запросов сохраняется исходная идея/шаблон в пользовательском локальном рецепте; они восстанавливаются, если запрос и ответ доступны на загруженной странице текущей беседы. Старые файлы, другая беседа/страница истории либо другой браузер используют фактический generation.prompt/options. Полное восстановление исходного задания для всех файлов не заявляется.
- **Ожидание/ошибки:** сохраняются существующие реальные статусы, предупреждение об ошибке и ручная повторная отправка; карточки planner/уточнения как у дизайнера не реализованы. Новых backend API, миграций и изменений баланса этим этапом нет.
- **Просмотр изображения (дополнение пользователя):** сетка/история/библиотека через Media выбирают READY-превью, при отсутствии/ошибке используют оригинал. В большом HomeImageViewer страницы изображений теперь сначала показывается доступное превью, затем оригинал; кешированная загрузка проверяется через complete/naturalWidth. Ожидание ограничено 30 секундами, поздний успешный ответ восстанавливает оригинал, ошибка сохраняет превью. Большой MediaPreview библиотеки по-прежнему загружает оригинал; не утверждаем, что все экраны показывают исключительно превью. Backend превью не менялся.
- **Проверено:** сборка, 338 unit-тестов (testTimeout=15000: прежний 5-секундный лимит deploy-rollback теста превышался локально), применение всех 130 шаблонов, фильтры избранного во всех трёх реализациях, восстановление рецепта/референса, медленный и ошибочный оригинал. Браузерные тесты используют тестовый API. Сравнение с прототипом при одинаковом размере выполнено через /tmp/gnosis-image-parity.cjs; меню избранного отличается намеренно, полное соответствие не заявляется.

## Как читать и обновлять

- **По коду** — изучена конкретная реализация, но успешный живой сценарий этим не доказан.
- **Проверено локально** — выполнено действие в браузере; уточняется, использовался ли тестовый API.
- **Реальная проверка** — запрос прошёл через Gnosis и реального провайдера.
- **Не проверено** — данных недостаточно. Это не синоним «невозможно» или «нужно менять backend».
- **Открыто** — требуется обсуждение или реализация. **Намеренное отличие** — основано на явном решении пользователя. **Исправлено** — устранён конкретный дефект, но не обязательно принят весь сценарий.

У пунктов постоянные идентификаторы. При изменении обновлять текущее состояние и подтверждение; важные прошлые результаты оставлять в истории проверок. Не превращать предложенное решение в согласованное без основания. Не записывать токены, секреты и временные подписанные ссылки.

## 1. Архитектура и процесс работы

### ARC-01. Проект и история — реализовано на другой основе

- **Документ:** единый проект с контекстом: бриф → уточнение → изображение → правка → видео → презентация; возврат после перезагрузки.
- **У них:** собственные проекты, сообщения, работы и серверные задачи. Исследованы клиент и серверная копия; полноценный платный сценарий на стороне заказчика не запускался.
- **У нас:** один проект представлен беседой Gnosis. Сообщения и файлы сохраняются сервером. `/chat?conversation=…` открывается в новом ContentStudio. Изображение и видео в одной беседе проверены реальными запросами.
- **Открыто:** отдельные проектные статусы, текущая задача и формальная структура версий не реализованы как самостоятельные сущности нового интерфейса.
- **Источники:** документ §7; `creatives-chat.js`, `creatives-store.js`; [useContentConversation.ts](../src/features/content-studio/useContentConversation.ts), [ContentThread.tsx](../src/features/content-studio/ContentThread.tsx).

### ARC-02. Планировщик и граф — существенное отличие, открыто

- **У них по коду:** платный image/video-запрос содержит `brief=true`. Серверный planner проверяет материалы и возможности модели, вызывает текстовую модель для структурированного плана, проверяет план и при необходимости пытается исправить его. Выключение сценариста не отключает planner.
- **У нас:** ассистент обычной беседы вызывает IMAGE или VIDEO. Используются проверки каталога Gnosis. **Граф не создавался и к беседе не подключался. Аналога их отдельного планировщика в новом подключении нет.**
- **Следствие:** работающий вызов инструмента не доказывает эквивалентность их подготовке и проверке плана.
- **Проверено по коду Gnosis:** AgentGraphService.listAvailableAsTool исключает графы с HUMAN; отдельно AgentGraphCompiler и AgentGraphRunService поддерживают interrupt/resume и isApproved. Поэтому пауза согласования существует, но не подключается автоматически как инструмент беседы. Медиа вызывается инструментами агента; сам граф не гарантирует соблюдение параметров и отсутствие повторов.
- **Открыто:** выбрать связь беседы с отдельным запуском/возобновлением графа и отображение согласования. Пока не установлено, нужен ли граф, сочетание беседы с графом или иной существующий механизм. Не считать изменение backend обязательным до такой проверки.
- **Источники:** `studio_gate.py::plan_job`, `planner/run.py`, `planner/prepare.py`; наши `ContentStudio.tsx`, `useContentConversation.ts`.

### ARC-03. Сценарист и принятие сценария — согласованное применение текста на клиенте

- **Документ §7:** исходный бриф сохраняется, сценарист уточняет детали и предлагает текст; применение сценария — явное действие пользователя.
- **У них по коду:** отдельный writer-запрос, затем автоматическое продолжение генерации. При выбранном шаблоне writer пропускается.
- **У нас:** текстовый запрос без медиинструментов; автоматического продолжения нет. По согласованию пользователя 2026-11-04 добавлено «Использовать сценарий» под текстовым ответом на сообщение `[Genfactory:script]`: переносит ответ в поле, восстанавливает файлы исходного сообщения, выключает сценариста и фокусирует поле. Пользователь редактирует текст и запускает генерацию обычной отправкой. Кнопка сама не отправляет запросов генерации и недоступна во время работы. Выбор шаблона сам по себе сценариста не выключает.
- **Открыто:** это применение текста на клиенте, не серверное состояние «сценарий утверждён» и не формальная связь принятой версии с запуском. Исходный бриф, ответ и отправленный текст сохраняются сообщениями. С 2026-11-05 кнопка консервативно проверяет наличие длительности и полей сцены; обычные уточнения/отказы не предлагаются как сценарий. Текст всё равно проверяет пользователь. Короткие команды подтверждения/генерации обработаны на frontend — см. текущий этап выше. Используются текущие модель и настройки; снимок настроек старого сценария не восстанавливается. Ограничения двух вкладок и повторных вызовов ассистента сохраняются.
- **Проверка:** реальный текстовый ответ в беседе 61. После добавления кнопки прошли TypeScript и 18 браузерных тестов студии с тестовым API, включая подготовку сценария с файлом → reload → применение без отправки → редактирование → отдельный VIDEO-запрос с тем же fileId без повторной загрузки. Снимок интерфейса просмотрен. Новая платная генерация в этом этапе не запускалась.
- **Источники:** `creatives-chat.js::runWriterThenModel`, `submit`; [prompt.ts](../src/features/workspace/prompt.ts), `ContentStudio.tsx`.

### ARC-04. Управление инструментами — ограничение текущей интеграции

- **У них:** сценарист и генерация разделены собственными запросами и серверными обработчиками.
- **У нас:** перед сценарием выполняется `PUT /conversation/:id` с `options.tools=[]`; перед генерацией — с выбранным IMAGE или VIDEO. Затем выполняется `POST /conversation/:id/message`.
- **Важный факт Gnosis:** `settings.tools` сообщения переопределяет настройки подключённых инструментов; пустой массив **не отключает** инструменты самой беседы. Поэтому первоначальное предложение ограничиться только настройками сообщения было неверным.
- **Открыто:** PUT и POST не атомарны. Две вкладки могут менять общие настройки одной беседы. Текущий интерфейс не предоставляет весь набор универсальных инструментов Gnosis; их отсутствие здесь не означает отсутствия в backend.
- **Источники:** `AiToolSettings.overrideConnections`, `ConversationMessageAddController`; `useContentConversation.ts`.

### OR-03. TTS — подтверждённая ошибка описания форматов, исправление связано с сохранением

[Документация TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts): форматы mp3/pcm, Gemini TTS только pcm. Наш `OpenRouterTtsOptionsSchema` использует общий список сохраняемых аудиоформатов и default=mp3 для всех; voice — свободная строка, speed — число без модельных ограничений. Это не точное описание возможностей конкретной модели. Три наших ID найдены в `/models?output_modalities=speech`.

Проверка предполагаемой правки выявила, что `TtsTool` не сохраняет raw PCM (`Audio format "pcm" cannot be saved as a recording`).
