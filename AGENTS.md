# Genfactory: обязательные требования пользователя

## Ревью перед каждой выкладкой

Пользователь подтвердил 2026-11-13: базовая метка проверки — последняя `astra` среди тегов и сообщений коммитов. Проверять все изменения после этой метки, включая закоммиченные и локальные. Перед выкладкой пользователь проверяет код мощной моделью на соответствие его ООП-паттернам, стилю и логике. Подготовить код и результаты проверок для этого ревью; выкладывать после завершения проверки и команды пользователя.

При переносе интерфейса воспроизводить предоставленный прототип **1:1**.

- Источник: опубликованный прототип в `../prototype` (локально http://127.0.0.1:5177/). Рабочий frontend: этот репозиторий (http://127.0.0.1:5173/).
- Сохранять состав и порядок блоков, тексты, иконки, изображения, видео, шрифты, цвета, яркость фона, размеры, отступы, разделители, состояния и анимации оригинала.
- Не добавлять от себя подписи, кнопки, разделы, пояснения или улучшения. Не заменять элементы приблизительными аналогами.
- Любое отступление, включая ограничения текущего backend и отличия поведения, сначала объяснить пользователю и согласовать. Не придумывать замену самостоятельно.
- Перед изменениями изучить соответствующий HTML/CSS/JS прототипа. После изменений сравнить в браузере при одинаковом размере окна; не заявлять полное совпадение без проверки.
- Работать по страницам. После каждого этапа показывать локальный результат для проверки пользователем; не переходить к следующей странице без согласования.
- Использовать Gnosis backend; изменения backend не входят в текущий перенос интерфейса без отдельного согласования.

Эти требования явно подтверждены пользователем 2026-11-03 после замечаний о самовольных отличиях от оригинала.

## Реестр фактического состояния

По требованию пользователя от 2026-11-04 вести отдельный актуальный файл [docs/IMPLEMENTATION-DIFFERENCES.md](docs/IMPLEMENTATION-DIFFERENCES.md). При новых находках и изменениях обновлять соответствующие пункты: требования заказчика, фактический прототип, текущая реализация Gnosis-клиента, уровень проверки, источники и открытые вопросы. Отличать локальную реализацию от стенда, код от реального запуска, предложение от принятого решения. Не выдавать наличие UI за работающую функцию и непроверенную возможность Gnosis за отсутствующую. Историю этапов хранить отдельно от текущего реестра.

## Подтверждённые ограничения моделей

2026-11-04: пользователь разрешил без отдельного согласования исправлять подтверждённые ошибки в настройках/описании возможностей конкретных моделей, включая backend-каталог и соответствующую валидацию. Не переносить ограничение одной интеграции на другие модели без доказательства. Остальные изменения логики backend по-прежнему согласовывать; диагностические логи разрешены.

## Актуальное ограничение backend — 2026-11-04

Последнее указание пользователя: любое изменение backend сначала спрашивать и проектировать вместе. Это правило заменяет прежнее разрешение исправлять каталог без отдельного согласования. В текущем этапе разрешено подключение библиотеки на frontend через существующие API.
